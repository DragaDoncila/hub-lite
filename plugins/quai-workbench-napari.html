    quai

    quai-workbench-napari

    napari plug-in to create ground-truth data for quai.

    • Aaron Ponti
    View project data

    napari plug-in to create ground-truth data for quai.

    Annotations are kept in an annotation project: a folder that records every sample, every saved version of its labels, and the source image each sample came from, so annotation work is traceable and can be resumed at any time.

    Supported: single-channel 2D images and 3D (ZYX) volumes in TIFF files, with semantic labels (each pixel value is a class); random regions of the project's crop size, from all source images or from images selected by quai select-samples; predictions from quai to correct; exports that quai storage import-annotations versions for training. Planned later: choosing regions on an overview of the whole image (with OME-Zarr support), instance labels, and multichannel images.

    For a standalone walkthrough with practice images and optional quai integration, see Tutorial 14: quai annotation workbench. The complete quai tutorials are available to quai users on request.

    Install

    Install uv once.

    Install quai-workbench-napari

    Create an environment (Python 3.12 or newer) and install the plug-in with its dependencies. Annotating does not need quai or a quai license. Working with quai's outputs (selections, predictions, quai storage import-annotations, and 3D in particular) needs quai 0.4.0 or newer.

    The example uses Python 3.12; uv downloads it if needed.

    uv venv --python 3.12 .venv
source .venv/bin/activate        # Windows (PowerShell): .venv\Scripts\Activate.ps1
uv pip install "napari[all]" quai-workbench-napari

    If you also use quai-atlas, install both into one environment with Atlas's napari extra instead, which brings napari and the workbench:

    uv pip install "quai-atlas[napari]>=0.2.0"

    Atlas then opens images and starts the workbench with its own Python, with nothing to configure. Don't add napari[all] to that environment: it would install a second Qt binding (PyQt) next to Atlas's PySide6. See Atlas's README or Tutorial 15, section 9.

    Annotating

    Start napari and open Plugins → Annotation workbench (quai).

    $ napari

    Create or open a project

    • New project asks for:
      • a project folder (new or empty), where the project will be stored;
      • the source images folder (2D TIFF images, or ZYX stacks for a 3D project; subfolders are included). Source images are only read, never modified;
      • a project name;
      • the classes, comma-separated in label order, background first (label 0). For example background, nucleus, border gives labels 0, 1, and 2;
      • the crop size of the regions to annotate (default 512×512). Smaller regions are quicker to annotate, but more context may help the neural network learn;
      • the maximum overlap allowed between regions taken from the same image (default 20 %).
    • Open project opens an existing project folder. If the source images have moved, you are asked to locate them.
    • A project can be edited by one napari session at a time. If it is open elsewhere, you are told where; take over only if that session has ended, otherwise its unsaved work may be lost.

    Enter your name under Annotator to have it recorded with each saved version. The name is remembered for you on this computer (it is not stored in the project, which colleagues may share). Under the field, the panel shows who saved last and when, so you can tell whether the name is right before continuing someone else's work. Saving without a name works, but the status line points it out. "Completed regions" and "Saved drafts" count the current saved state of each region once, across the whole project. Unsaved edits do not change these counts until saved. Hover for contributors, historical revision counts, and dates. To list them without opening napari:

    $ quai-wb-annotators /path/to/project          # or --json

    Annotate

    • Next random crop picks a random region of the chosen size from a random source image, respecting the maximum overlap with regions already saved. The image and an empty Annotation layer are added to napari.
    • Paint the labels in the Annotation layer. The legend in the panel shows which label value is which class.
    • Save draft stores the labels as a draft. You can save as often as you like; each save is kept as a new version.
    • Complete offers Complete, Save draft, Discard changes, and Cancel when labels differ from when the region was opened. Choosing Complete saves and marks the region as fully annotated. Only completed regions are used for training. If a region contains nothing of interest (only background), still complete it: the network also needs to see such areas.
    • Revert discards edits made since the last save.
    • Editing a completed region turns it back into a draft until you complete it again.
    • The sample list shows every saved region and its state (draft or complete). Click a region to reopen it.
    • Before you move to another region, open another project, or close napari or the panel with unsaved edits, you are asked whether to Complete, Save draft, Discard changes, or Cancel.

    Labels with values that are not classes of the project are refused with a message; nothing is saved.

    3D (volumetric) projects

    Choose 3D (ZYX) under Images in New project to annotate single-channel ZYX stacks (TIFF; channel and time axes are not supported).

    • Regions are subvolumes. Set their size per axis (default 16 × 96 × 96 voxels); it should cover the training patch of your quai campaign. A stack without axis metadata is read as ZYX.
    • The voxel spacing is read from OME-TIFF or ImageJ metadata when it is complete for all three axes (in nm, µm, or mm). Otherwise you are asked for it the first time you save a region of that stack; known values are filled in. You can also set a project default for stacks without metadata, at creation or in the spacing dialog. While the project has no default, the first prompt offers the entered spacing as the default (untick it if your stacks differ), so stacks without metadata, including selected stacks already in the queue, are not asked one by one. Spacing shows or changes the current stack's spacing; changed values are recorded as user-supplied. Use it only to correct a missing or wrong calibration: it changes the recorded spacing and the display scale, not the pixels. When stacks have different spacings, a note lists them: when a save or import first makes them differ, when the project is opened, and before an export that contains them. quai's default 3D campaign transforms work with one spacing per dataset; to train on several spacings, specialize them, otherwise annotate stacks of each spacing in a separate project. The Spacing dialog's checkbox shows whether the current spacing is also the project default.
    • The subvolume opens at its middle slice, scaled by its spacing. Paint slice by slice in napari's 2D view, moving through Z with the slider. napari's 3D view shows the whole subvolume; there, napari only edits voxels that already have a label (repainting and erasing work, painting on background does nothing). Save draft, Complete, Revert, and Discard changes work on the whole subvolume. There is no per-slice completion: Complete means every slice of the subvolume is annotated.
    • Training in quai: the export records each sample's spacing, but quai's 3D campaign transforms do not read it. Set the run's voxel_size to the recorded spacing and choose a patch_size (in the resampled space) that fits the subvolumes; see quai's annotation import guide. quai storage import-annotations reports a note when an export has several spacings.
    • Selected stacks and their predictions work as for 2D images (see "Annotating images selected by quai"): Next region from the selection draws a random subvolume of the next selected stack, prefilled with the matching part of its prediction. Whole stacks are never opened.
    • If cells span many slices, most of them touch the top or bottom of a thin subvolume; a deeper subvolume (more Z slices) leaves more cells whole.

    Two kinds of project

    A project is made for one purpose, fixed when it is created, and shows only the buttons for it:

    • Manual project (New project): annotate the images of a folder from scratch. Next random crop draws regions of any image in the sources folder. Nothing is imported from quai.
    • Selection project (New project from quai selection): correct the predictions of the images one quai select-samples run chose. Next region from the selection draws regions of the selected images in rank order. Make one selection project per round of the active-learning loop.

    Both export completed regions for quai the same way. Projects made by earlier versions of the workbench, before projects were manual or selection projects, can't be opened: export their completed annotations with the version that made them, then create a new project.

    Annotating images selected by quai

    quai select-samples picks the images a model is most uncertain about. To annotate them:

    • Choose New project from quai selection and the folder quai select-samples wrote (with selection_manifest.json and selected_images.csv). That is the only folder you choose, also when the experiment and data folders were copied, moved, or opened from another computer or share.
    • The plug-in finds the selected images, the model's classes and the uncertainty analysis from quai's records, and checks each image's content against what quai recorded; an image with other content is refused. If a recorded folder can't be found (for example a data repository on another share), you are asked once where it is on this computer; the answer is remembered (Remembered folders lists and forgets them).
    • It proposes the project: the folder the uncertainty analysis read (the pool) as the source images folder, the model's classes in its order, and a name. It says whether predictions of the images were found. You choose where to keep the project; nothing is created if none of the images can be queued. A project that was open stays as it is.
    • The selected images join the selection queue in rank order, with their rank, score and the selection's provenance; nothing is opened or copied yet.
    • The runs in the experiment that predicted the selected images are offered, with the model each was made with (the selection's own model first; runs with identical predictions of these images are offered once). Choose one, or decline: regions then open with empty labels.
    • Find predictions looks again, for example after you ran quai full-inference on the selected images. A project's predictions come from one model: a run of that model fills only images without a prediction; a run of another model replaces them only if you confirm, and only if it predicts every image that has one. Saved regions never change. If the project's selection folder has moved, you are asked for it, and it is checked against the one recorded in the project.
    • Next region from the selection draws a random region of the next image in the queue, of the project's crop size (the whole extent along axes where the image is smaller), with the overlap limit, prefilled with the matching part of its prediction. Annotate, Save draft, and Complete as usual. Each region records the image's selection rank, score, and metric; both are carried into exports.
    • The queue takes the images in turn and wraps around, so each image gives one region per pass; it continues where it left off after a restart. An image with no room for another region under the overlap limit is passed over and named in the status line. Selection queue lists the images with their status and number of regions; Done with this image and Skip take an image out, Put back in queue returns it.
    • Regions are random on purpose: choosing them by hand favours easy regions. Showing the whole image to choose a region is planned with OME-Zarr support.

    Correcting predictions

    • A prediction is attached to the image of the same name only if it has the image's shape and its labels are the project's classes, in the same order. When the prediction run keeps an output list (quai 0.4.0), the prediction must be in it, unchanged, and the image must be the one it was made from (the same content); otherwise it is refused.
    • For an ensemble, the fused prediction (ensemble_<name>.tif) is used, not the individual models'. Predictions never become ground truth on their own, and never replace a region you have saved.
    • A region's prediction is stored with the region when you first save it, so the prediction folder is not needed afterwards. If the prediction file was moved or changed before then, you can continue without it or locate the folder it was moved to.
    • Edit the labels and Complete. For labels changed since opening, the dialog offers Complete, Save draft, Discard changes, and Cancel. Complete keeps the labels and records an unchanged prediction as accepted, or changed labels as corrected, automatically. Discard changes restores the labels from when you opened the region without saving or completing it; earlier explicit saves remain in history, so the restored labels may be unsaved relative to the latest save. Cancel keeps editing without writing anything. Revert continues to restore the last saved labels. Existing rejected decisions remain readable and exportable; the dialog no longer creates them.
    • Correcting a prediction run's output without a selection is not offered in new projects. To correct the predictions of a whole pool, run quai select-samples with --k at least the number of images.

    Do not edit these files by hand. The format is specified in annotation-record-schema-v1.md.

    Reviewing saved drafts

    The sample list offers All, Drafts, and Complete filters with counts. Next draft cycles through saved unfinished regions. Next region from the selection draws regions of the selected images.

    When leaving an edited region or completing it, use the same choices: Complete saves and makes it eligible for export; Save draft saves unfinished work; Discard changes restores opening labels without writing; Cancel keeps editing. Cancelling panel closure reopens the panel. Explicit earlier saves remain in history. Revert still restores the most recently saved labels.

    Complete all drafts previews the affected samples and requires confirmation that all are fully annotated, including imported predictions. Every draft passes full pixel validation before one project-record replacement completes the batch; if validation fails, none is completed.

    Discard all drafts previews how many samples will return to a completed annotation and how many will become unannotated. Confirmation appends discard events in one project-record replacement, preserving all revisions and blobs. Never-completed samples reopen without labels and can receive predictions again. New edits can be saved afterward, retaining the historical revision chain. These discard events are an optional project-record extension; use the updated plugin to reopen projects containing them. The export format is unchanged.

    Scope of the controls

    • Current region: Save draft, Complete, Revert; Revert restores the last save.
    • Sample navigation: Next random crop (manual projects), Next region from the selection (selection projects), Next draft.
    • Saved drafts (whole project): Complete all drafts and Discard all drafts.
    • quai selection (selection projects): Find predictions, Selection queue, and Remembered folders. Predictions open with the regions drawn from predicted images and never replace manual annotations.
    • Export (completed annotations): Export for quai.

    Controls are disabled when there is no eligible region, queue, draft, or completed annotation. Edit controls update as labels change; all controls stay disabled while a worker runs. Every region of a project shares its class mapping and the overlap limit. Each sample retains its own geometry; prediction files must match the source shape before a region is cut from them.
